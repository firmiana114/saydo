# 一次运行，采集一组D435i与D405标定候选

`capture_pair.py` 供固定D405通过已有眼在手D435i连接到一号臂Base的标定使用。每次运行创建一个独立样本目录，然后退出；不循环收集、不自动重试、不驱动机械臂、不切换工具或工作坐标系，也不求解/发布D405外参。

机械臂与标定板可以在两组之间改变姿态。每组采集过程中两者须保持静止，D405支架和D435i相对法兰的安装保持不变。

## 采集前

1. 整个采集阶段关闭8089，使D435i不再被定位服务占用；结束采集后再恢复定位服务。不应在存在活动任务或需保留夹持关系时停止8089。脚本自身不会终止其他进程。
2. 8088双路服务保持运行。开启双路预览，确认D435i、D405状态均为直接采集、1280×720。若先前D435i仍显示共享8089，先释放本页D435i预览再重新开始。没有预览时脚本也会建立自己的临时观看连接，结束只关闭自身连接。
3. 在两台相机的共同视野内摆好棋盘，完整看见全部内角点；保持板平整、停稳。
4. 当前默认棋盘为8×11内角点、30mm格长，沿用既有标定定义；请实测确认。有不同棋盘时显式传入`--columns`、`--rows`、`--square-mm`，并使用新会话。
5. 示教器保持零变换`Base`工作坐标系。支持非零工具偏移：只读获取当前工具，并用`base_T_tcp @ inverse(flange_T_tcp)`计算实际法兰位姿，无需切换到零工具。

## 一组采集

在MSI的项目根目录运行：

```sh
.venv/bin/python tools/handeye/capture_pair.py --session d405_base1_01
```

每次摆好新的板/机械臂姿态并停稳后，再运行相同命令。每次自动生成唯一目录，不覆盖前一组。默认数据角色为`training`；保留独立验证组时运行：

```sh
.venv/bin/python tools/handeye/capture_pair.py \
  --session d405_base1_01 --role validation
```

其他棋盘的命令示例（尺寸必须填写实测值）：

```sh
.venv/bin/python tools/handeye/capture_pair.py \
  --session another_board --columns 8 --rows 11 --square-mm 30
```

`--monitor-url`默认`http://127.0.0.1:8088`，`--robot-ip`默认现有控制器`192.168.1.19`。相机身份读取机器本地`config/cameras/global.json`，既有手眼矩阵/同安装复用依据读取`config/calibration/`。校验既有标定原始记录摘要，保存当前来源与验收边界，不改写配置。

## 检查与输出

脚本先检查机器人身份、工具/工作坐标系和静止反馈，再并行读取两路原生新帧；连续采两对图像，用第二对检查板静止。拒绝640×360、JPEG或缺失实际内参的输入，不把JPEG转存PNG冒充无损原图。

当前筛选门槛：

- 机器人反馈两两比较：关节跨度≤0.03°、TCP位置跨度≤0.2mm、朝向跨度≤0.15°。
- 两路每对主机时间差≤200ms，图像新鲜度≤600ms；两对采集被实际机器人反馈包围，时间窗口≤1秒。
- 两次同机位角点最大位移≤1像素；完整找到棋盘角点，PnP重投影RMS≤1像素。
- 工具、工作坐标系、相机内参/身份及本机标定配置在本组期间保持一致。

这些是静态候选筛选门槛，不是硬件同步或最终标定精度保证。所有相机时间字段保留其依据；运动中采集不受支持。

数据位于：

```text
work/dual_camera_calibration/<session>/<唯一样本ID>/
  d435i.png                 原生1280×720彩色PNG
  d405.png                  原生1280×720彩色PNG
  d435i_check.png            第二次图像，用于板静止检查
  d405_check.png
  d435i_corners.jpg          带角点原点/+X标注的检查图
  d405_corners.jpg
  sample.json               位姿、工具偏移、内参/畸变、时间、角点、哈希和质量结果
```

会话`session.json`绑定棋盘尺寸、两路内参/身份、手眼来源和角点顺序。机械臂位姿可以变化；上述定义变化时需使用新`--session`。会话锁拒绝同时采集同一会话。

输出`status=candidate`、退出码0表示本组静态质量筛选通过；不是标定完成。`status=rejected`、退出码2表示本组未通过，目录及已获取的图像/原因保留，运行新命令采下一组；不会自动重试。基础参数/会话锁或其他程序入口错误退出码1。

## 棋盘角点方向须核对

普通棋盘可能存在180°角点顺序歧义。检查两张`*_corners.jpg`中的红色`0 / origin`是否落在同一个物理角点，`+X`是否沿同一物理方向。脚本保存全部正深度PnP候选，明确标记需审阅，不自动把两路的最小误差候选当作已确认共同原点。

如人工确认D405角点编号与D435i恰好反向，可在新会话采集时指定`--d405-reverse-corners`，同会话保持一致。该选项不是替代物理方向核验；已经采集的文件不会被改写。

已有D435i采用更换相机后同安装复用的手眼关系，样本保留`replacement_accuracy_verified=false`等来源信息。双相机候选质量通过不证明到机器人基座的绝对精度；后续仍需多组求解、共同角点原点核对与独立验收。
