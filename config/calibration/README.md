## 单位与坐标方向

- `A_T_B` 将 B 坐标中的点转换到 A 坐标中，使用列向量、左乘矩阵。
- 变换矩阵中的平移统一为米，RPY 为弧度，旋转顺序为 `Rz(yaw) @ Ry(pitch) @ Rx(roll)`。
- 相机参考系是 `color_optical_frame`，不能直接替换为 `camera_link` 或深度光学坐标系。
- `flange` 是本项目的逻辑名称，接入 ROS TF 前必须核对实际机器人末端 link；本目录没有猜测或配置 ROS link 映射。
- 验证统计保留原结果字段中的单位，例如 `translation_error_mm`、`rotation_error_deg` 和像素误差；内参 K 使用像素单位。
- 控制器原始回复仅作为溯源记录，其中位置整数的单位为 0.001 mm、角度整数为 0.001 rad。程序应使用 SI 字段，不能直接使用原始整数。

## 后续运行程序的接入约定

以下静止采集检查已在 `tools/object_scan/capture_view.py` 实现；实时 ROS 和运动控制仍需各自实现对应检查，不能复用静止采样来声称动态同步：

1. 校验 schema、单位、有限数值、4×4 齐次矩阵及旋转正交性，确认两份配置属于同一安装。
2. 从控制器只读查询当前工具，核对名称、完整六维工具位姿及负载参数；不一致时停止本次操作并报告差异，不自动覆盖任一方。
3. 核对工作坐标系为零偏移 `Base`；否则先完成工作坐标到基座坐标的变换，不能直接把反馈当作基座坐标。
4. 核对真实相机序列号、当前图像分辨率及内参；本次 K 对应 1280×720 彩色图。RGB、对齐深度与 mask 必须位于同一像素坐标系。
5. 明确 TCP 尚未完成几何验证；只读感知接入与后续物理抓取采用不同的验收范围。运动时还需要匹配图像时刻的机器人反馈。

当当前工具是 `grip_tcp`，且反馈位姿位于 `Base` 时：

```text
base_T_flange = base_T_grip_tcp @ inverse(flange_T_grip_tcp)
base_T_object = base_T_flange @ flange_T_color_optical_camera @ camera_T_object
```

不要把当前 TCP 位姿直接当作法兰位姿；不要只从基座 Z 数值减去 0.1905 m，因为工具局部 Z 会随机械臂姿态旋转。

## 更新规则

- 原始采集和求解结果保持不变。重新标定应保留新的结果版本，并在确认后更新 YAML 的矩阵、来源哈希和状态。
- 工具位姿或负载发生变化后重新读回并更新工具配置，不能只修改工具名称。
- 相机安装、夹指或转接件变化时重新核对适用性；未知信息保留未确认，不用估算值冒充实测。
- 参数变化通过 Git 追溯；不要将设备凭据、原始图像或大量运行日志放入本目录。
