# 按臂角求逆解：让程序自己决定手肘怎么摆

本文说明规划时“由夹爪位置反算关节角”这一步现在是怎么做的、为什么这样做。代码在 `saydo/robot/ik/`，Python 一侧的入口是 `saydo/robot/motion_validation.py` 的 `check_waypoints`。2026-10-10 上线。

## 它解决什么问题

规划一个动作时，程序先定出夹爪要经过的一串位置和朝向（下称**路点**），再为每个路点算出 7 个关节各转到多少度。后一步叫**逆解**（inverse kinematics）。

这台机械臂有 7 个关节，而确定夹爪的位置和朝向只需要 6 个量，多出来 1 个自由度：**夹爪固定不动时，手肘还可以绕“肩到腕”的连线转动**。转过的角度叫**臂角**（arm angle）。可以用自己的手臂体会：手掌按在桌上不动，手肘仍然能抬起、放下。

原来的做法调用厂家算法库的通用逆解函数。它在内部把臂角扫一遍，自己挑一个结果交回来，程序无法指定。于是有三个问题：

| 问题 | 表现 |
| --- | --- |
| 避不开障碍物 | 手肘摆在哪一侧由函数决定。它挑的那一种碰到立杆时，程序只能否决整个方案，换不出别的摆法 |
| 分不清“没有解”和“没找到” | 为了得到不同的摆法，程序换 31 个不同的参考值各调一次，指望它因此挑出不同的臂角。全部失败时，不知道是真的走不通，还是没碰上 |
| 慢 | 每个路点、每条候选路线都要调 31 次，每次内部又扫一遍臂角 |

2026-10-10 上午的实例：试管在 1 臂基座坐标 (195, −273) 毫米处，离立杆约 27 厘米。固定抓放规划 60 秒内试了 192 个候选方案，无一通过，绝大多数的原因是“求不出连续的关节解”。

## 现在的做法

厂家算法库里另有一个函数 `rm_algo_inverse_kinematics_rm75_for_arm_angle`：给定夹爪位姿和**指定的臂角**，用公式直接算出关节角，每次不到 1 微秒。程序改用它，自己把手肘的摆法一个个列出来再挑选。

```text
路点 1 ──► 路点 2 ──► 路点 3 ──► …… ──► 最后一个路点
   │           │
   │           └ 每个路点都做同样的事
   ▼
① 把这个夹爪位姿下手臂的摆法列出来
② 去掉超出关节限位的、会碰到桌面或立杆的
③ 与上一个路点保留下来的摆法连接，算出转动量
④ 保留 16 个：最省力的，加上与它差别大的
⑤ 对保留的再查：自碰撞、算回夹爪位姿是否一致、走过去的途中是否碰撞
全部路点走完后，取总转动量最小的那条路径
```

### 第 ① 步：同一个夹爪位姿有多少种摆法

| 可变的东西 | 取法 | 说明 |
| --- | --- | --- |
| 臂角 | 一整圈，每 5 度一个，共 72 个 | 手肘绕“肩到腕”连线转到哪里 |
| 手肘弯向 | 2 种 | 第 4 关节取正角度还是负角度 |
| 肩部分支 | 2 种 | 第 1、3 关节各加 180 度、第 2 关节取反，夹爪位姿不变 |
| 腕部分支 | 2 种 | 第 5、7 关节各加 180 度、第 6 关节取反，夹爪位姿不变 |
| 第 7 关节多转一圈 | 最多 3 种 | 它的活动范围是正负 360 度 |

合起来每个路点最多约 1700 种，去掉超限位的通常剩几百种。厂家函数每个臂角、每种手肘弯向调用一次，其余几种由程序按上表的对称关系直接写出，不需要再调用。

直线段上的取样点（相邻两点关节角变化不得超过 10 度）不做这样的全量列举，只沿上一个解继续走：臂角保持不变，或偏开 2 度、5 度。偏开的几种让手肘能在直线运动中一点点转开，绕过限位或障碍物。

### 第 ② 步：搜索时就避开障碍物

碰撞检查（见 [`collision_check.md`](collision_check.md)）原先只在逆解全部完成之后做一次，发现会碰撞只能否决。现在检查器在挑选摆法时就做：外形（运动学参数、13 个胶囊体）和障碍物（桌面高度、立杆位置与余量）由 Python 随每次请求传给检查器，检查器用同一套算法（`arm_collision.h`）计算。

尺寸只在 `collision_model.py` 里保存一份。检查器找到路径之后，Python 仍用 `collision_model.check_path` 沿整条路径再核对一遍，它才是最终放行的依据。检查器的判断比它严 0.2 毫米，避免两边因计算精度不同而在边界上结论相反。`tests/robot/test_arm_collision_native.py` 用同一批随机姿态对比两种实现。

### 第 ④ 步：为什么要保留“差别大的”

只保留最省力的那种摆法时，它可能在后面某个路点走进死路，而另一种摆法本来走得通。所以每层的 16 个名额先给彼此差别大的摆法（任一关节相差 45 度以上的先选，再放宽到 15 度、1 度），最后才按转动量补满。

## 失败时能说清原因

搜索卡在某个路点时，检查器把这个路点的全部摆法列出来再下结论：

| 类型 | 含义 | 是否确定 |
| --- | --- | --- |
| `out_of_reach` | 任何摆法都够不到，或都超出关节限位 | 确定。换路线、换夹持方向才有用 |
| `blocked_by_obstacle` | 够得到，但所有摆法都会碰到桌面或立杆 | 确定（在臂角 5 度一格的精度内） |
| `no_continuous_solution` | 这个位姿有可行的摆法，但从前面的路径走不过去：关节角变化过大、途中碰到障碍物或自碰撞 | 不确定。每层只保留 16 个解，可能是前面选的摆法不合适 |
| `budget_exhausted` | 超出时间预算 | — |

通过时，记录里的 `arm_angles_deg` 是每个路点采用的臂角，`collision_check` 是全程离桌面和立杆最近多少。

## 实测效果

都是只做计算的回放和只规划试算，**没有在真实机械臂上执行过**。

| 对比项 | 原来 | 现在 |
| --- | --- | --- |
| 最近 16 次历史固定抓放方案，带立杆碰撞检查回放 | 13 次找不到方案 | 16 次全部找到 |
| 其中第一个候选就通过的 | — | 8 次，约 0.2 秒 |
| 其余 8 次 | — | 2～5 秒，都用“边走边翻”；原地翻被判为够不到或被障碍物挡住 |
| 2026-10-10 桌上的真实场景（试管离立杆 27 厘米） | 60 秒无解 | 第一个候选通过，规划约 1.5 秒，全程离立杆最近 36 毫米（肘部） |
| 检查一条 66 个路点的路径 | 约 470 毫秒 | 约 40 毫秒 |
| 同一条路径的关节转动总量 | 1100 度 | 993 度 |

16 次里有 6 次的方案离立杆 30～31 毫米，贴着 30 毫米的余量。原因是搜索只求转动量最小，余量是硬门槛，不会主动离得更远。

## 摸清厂家函数行为的几项实验

这个函数的说明只有一句话，下面几点是实测得到的（2026-10-10，算法库 1.1.5 版），程序的做法依赖它们：

| 事实 | 怎么测的 | 程序因此怎么做 |
| --- | --- | --- |
| 返回的手肘弯向总是与参考值的第 4 关节同号 | 2 万组随机位姿、臂角、参考值，无一例外 | 两种弯向各给一个参考值，各调一次 |
| 肩和腕返回哪个分支取决于参考值，没有简单规律 | 用翻转过的参考值去取 8 个分支，只取到约四分之一 | 不依赖它，按对称关系自己写出其余分支 |
| 它挑中的分支超限位时直接报失败，不改试别的分支 | 同一位姿、臂角下，随机参考值约一半报超限位 | 把算法库里的限位放宽，让它总能给出一个解；真实限位由程序逐个核对 |
| 参考值的第 2、4、6 关节为 0 时求解失败 | 这三种参考值下，一圈 72 个臂角全部失败；换成普通参考值后全部成功 | 参考值固定取避开这些位置的一组数 |
| 放宽限位后，一圈 360 个臂角都能解出，相邻 1 度之间关节角变化不超过 1.6 度 | 逐度扫一圈 | 臂角可以当作连续可调的量 |
| 由关节角算臂角再按该臂角求解，能还原原来的关节角 | 2000 组随机关节角，1999 组还原 | 沿上一个解继续走时，用它的臂角作起点 |

放宽限位只发生在检查器这个独立的小程序里，每次运行重新设置，不影响控制器。

## 尚未解决和没有验证的

- **没有实机验证。** 与防撞阶段二、出画检查等一起，等阶段四完成后统一做。
- 控制器的直线运动（`movel`）仍由控制器自己决定手肘怎么摆。固定抓放全程用关节运动，不受影响；页面抓取的接近、抬升和桌面放置的下降还在用 `movel`，待改成优先逐点关节运动。
- 方案可能贴着立杆的 30 毫米余量走。需要更保守时调大 `config/calibration/workspace_obstacles.yaml` 里的 `margin_m`。
- `blocked_by_obstacle` 没有区分挡路的是桌面还是立杆。
- 被夹着的物品、夹爪上的相机、另一台机械臂仍不在碰撞模型里。

## 名词速查

| 名词 | 含义 |
| --- | --- |
| 逆解（inverse kinematics） | 由夹爪的位置和朝向反算各关节角 |
| 正解（forward kinematics） | 由各关节角算出夹爪的位置和朝向 |
| 臂角（arm angle） | 夹爪不动时，手肘绕“肩到腕”连线转过的角度 |
| 路点（waypoint） | 规划出的夹爪要经过的一个位置和朝向 |
| 胶囊体（capsule） | 一条线段加一个半径，即两头是半球的圆柱，用来近似手臂的一段 |
| 束搜索（beam search） | 逐层推进、每层只保留有限个最好的候选的搜索方法 |
| 关节运动（`movej`） | 各关节同步转到目标角度，途中的关节角可以预知 |
