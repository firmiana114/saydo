# 机械臂与桌面、立杆的碰撞检查

本文说明程序怎样判断一次动作会不会让机械臂或夹爪碰到桌面和桌上的立杆：检查了什么、没检查什么、数据从哪来，以及后续几个阶段的安排。

## 为什么需要

逆解（由夹爪的目标位置反算各关节角度）和路径检查原先只看夹爪参考点这一个点。手肘、前臂、手腕和夹爪本体占多大地方，桌上立着一根装全局相机的杆子，程序都不知道。RM75 有 7 个关节，同一个夹爪位置对应很多种手臂摆法，逆解完全可能挑中手肘伸向立杆的那一种。

2026-10-09 的回放说明了这一点：当天 15:35 那次 1 臂实机抓放，按实际下发的关节角计算，肘部和前臂在调姿到入孔的过程中经过了立杆现在所在的位置（模型算出的间距最小为 −69 毫米，即重叠）。用户确认那次确实把立杆碰倒了。这个方案在加入本检查后会被拒绝。

## 检查什么

| 对象 | 规则 |
| --- | --- |
| 立杆 | 机械臂各段和夹爪离立杆表面至少 30 毫米（用户指定） |
| 桌面 | 肩部以上的各段和夹爪不得低于桌面，不留余量；底座和肩部固定在桌面上方，不检查 |

**没有检查的**（用户决定或尚未实现）：夹爪上的相机和支架、被夹着的物品、桌上的其他物品、全局相机本体、另一台机械臂。夹爪上的相机不在模型里，意味着“相机先碰到桌面”这类情况本检查拦不住。

## 外形怎么表示

每一段用一个胶囊体（capsule）表示：一条线段加一个半径，也就是两头是半球的圆柱。它算距离简单，又能把手臂的一段包住。定义在 `saydo/robot/collision_model.py`。

| 部分 | 数量 | 尺寸来源 |
| --- | --- | --- |
| 机械臂（底座加 7 个连杆） | 8 个，半径 39～74 毫米 | 厂家模型文件 `rm_description/meshes/rm_75_arm/*.STL` 逐段拟合，另加 1 毫米 |
| 夹爪 | 5 个 | 知行 CTAG2F90D 产品外形图 |

夹爪外形图上的关键尺寸：

| 尺寸 | 数值 |
| --- | --- |
| 闭合总长（安装面到指尖） | 222.5 毫米 |
| 张到最大时的总长 | 205 毫米（指尖缩回 17.5 毫米） |
| 张到最大时的总宽 | 151 毫米 |
| 行程（两指内侧间距） | 90 毫米 |
| 本体厚度 | 45 毫米 |
| 指垫宽度 | 23 毫米 |
| 安装座直径 | 75 毫米 |

这款夹爪是连杆式的，两指沿弧线开合：张开时指尖缩回、整体变宽。模型取“任何开度下都包得住”的范围，所以不随开度变化，偏保守。闭合指尖那个胶囊体的末端球面正好落在夹爪参考点上，因此竖直向下抓取时指尖贴近桌面不会被误判；夹爪放平或倾斜着靠近桌面时，本体和张开的手指的宽度会被算进去。

运动学参数（各连杆的位置怎么由关节角算出）与厂家模型逐连杆核对过，相差小于 0.02 毫米；与控制器读回的夹爪位置相差约 0.2 毫米。

## 什么时候检查

所有动作在规划时都经过同一个入口 `motion_validation.check_waypoints`。逆解和连续性检查通过之后，再做这项检查：

1. 把“当前关节角 → 第 1 个路点 → 第 2 个路点 → …”连成一条路径。
2. 相邻两点之间按关节角直线取样，任一关节每转 2 度取一个姿态。
3. 每个姿态算出全部胶囊体的位置，逐个比较离立杆和桌面的距离。
4. 有一处不满足就否决这个方案，报错写明是哪一段、走向哪个路点、差多少；有候选方案的流程会自动试下一个。

覆盖的动作：页面上的抓取、桌面放置、调姿、持物移动、固定抓放。复位是直接转到目标关节角，在发令前单独检查这一条路径，不通过时提示先手动把机械臂移到空旷处。

每次检查的结果（检查了多少个姿态、全程离立杆和桌面最近多少、最近的是哪一段）写在任务记录的 `collision_check` 里。

当前姿态本身不判：机械臂已经在那里，不是计划的一部分。但如果它已经在立杆的余量之内，离开的头几个取样点通常也在余量内，方案仍会被否决，需要手动移开。

## 障碍物数据

桌面高度取各臂抓取配置里的 `table_z_m`。立杆写在各机器本地的 `config/calibration/workspace_obstacles.yaml`（不入 Git）：

```yaml
schema_version: 1
pole:
  shape: vertical_square_bar
  side_m: 0.02        # 截面边长
  margin_m: 0.03      # 要求的最小间距
  position_m:         # 立杆中心，在各臂自己的基座坐标系里
    arm1: [-0.0782, -0.2633]
    arm2: [0.0740, -0.2442]
```

没有这个文件，或文件里没有某台臂的位置时，那台臂只检查桌面。立杆高度按无穷处理，方杆按外接圆（半径为边长的 0.707 倍）处理。

立杆位置的测法（2026-10-09）：让两只夹爪从相反方向夹住立杆，只读读取两臂位姿，取两指尖之间的中点。两臂各算一次，换到同一坐标后相差 6.6 毫米，取平均。记录在 `work/calibration/pole_touch_20261009.json`。**立杆被挪动过就要重新测。**

## 已知的局限

| 局限 | 影响 |
| --- | --- |
| 抓取和桌面放置仍用 `movej_p` | 这条指令由控制器自己做逆解，实际手臂摆法可能与我们检查的不同。阶段二会改掉 |
| 直线段（`movel`）按相邻取样点之间的关节角直线来检查 | 控制器实际的手肘摆法可能不同；固定抓放不发 `movel`，不受影响 |
| `movej` 是否严格走关节角直线没有实测过 | 检查的是理想路径；阶段三的运行记录会给出答案 |
| 夹爪按张到最大的外形算 | 倾斜着接近桌面上很矮的物品时可能被误拒 |
| 桌面按水平面处理（用户决定） | 实测桌面相对两臂底座各斜约 1 度 |
